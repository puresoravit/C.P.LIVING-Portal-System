# UAT Checklist — ทดสอบการใช้งานจริง

Automated Test ที่มีในโปรเจกต์ (`npm test`) ทดสอบเฉพาะ **Business Logic
ล้วนๆ** (คำนวณราคา/ส่วนลด/VAT/ปัดเศษ) ที่ไม่ต้องพึ่งฐานข้อมูลจริง —
**ยังไม่ครอบคลุม Integration Test แบบเต็ม flow ผ่านฐานข้อมูลจริง**
(เพราะเครื่องที่ใช้เขียนโค้ดนี้ไม่มี PostgreSQL ให้ต่อทดสอบ) เอกสารนี้
คือสคริปต์ให้คนทดสอบจริง (หรือ Claude Code ที่รันบนเครื่องมี DB) ไล่ทำตาม
ทีละข้อ

## ก่อนเริ่ม

- [ ] `npm install` สำเร็จไม่มี error
- [ ] `npm run prisma:migrate -- --name init` สร้างตารางครบ ไม่มี error
- [ ] `npm run prisma:seed` สำเร็จ (สร้าง admin user + Type A/B/C + VAT 7%)
- [ ] `npm test` ผ่านทุกไฟล์ (ควรเป็นสีเขียวทั้งหมด — ถ้าแดง แปลว่ามีบั๊ก
      ที่ยังไม่เจอ ให้แจ้งกลับมา)
- [ ] `npm run dev` รันขึ้นไม่มี error เปิด http://localhost:3000 ได้

## 1. Authentication & Permission

- [ ] Login ด้วย `admin` / `ChangeMe123!` สำเร็จ เห็นหน้า Dashboard
- [ ] สร้าง User ใหม่ Role BILLING_STAFF ผ่าน Prisma Studio
      (`npm run prisma:studio` — ยังไม่มีหน้า UI สร้าง User ใน V1)
      login ด้วย user นั้น → **ไม่ควรเห็นเมนู Dashboard/Report/ตั้งค่า**
      (ต้องเห็นแค่หน้าทางลัด "สร้างออเดอร์ใหม่")

## 2. Master Data (Golden Path)

- [ ] สร้างลูกค้า "ABC" รหัส `ABC01`, Credit Term = เงินสด
- [ ] สร้างสาขา "สาขา 01" ของลูกค้า ABC
- [ ] เพิ่ม Product Type "TYPE D" ทดสอบว่าเพิ่มได้โดยไม่ต้องแก้โค้ด
- [ ] สร้างสินค้า M001 (Type A, ราคา 1,000), M002 (Type A, ราคา 1,000),
      B001 (Type B, ราคา 2,000), P001 (Type C, ราคา 500)

## 3. Golden Test Case เต็ม (ตามข้อ 66 — สำคัญที่สุด)

- [ ] ตั้ง Discount: ABC/สาขา01, TYPE A = 10%, มีผลตั้งแต่ 01/01/2026
- [ ] ตั้ง Discount: ABC/สาขา01, TYPE B = 15%, มีผลตั้งแต่ 01/01/2026
- [ ] ตั้ง Discount: ABC/สาขา01, TYPE C = 20%, มีผลตั้งแต่ 01/01/2026
- [ ] สร้าง Order: ลูกค้า ABC, สาขา 01, วันที่ 19/08/2026
- [ ] คีย์: M001×10, M002×3, B001×5, P001×20
- [ ] **ตรวจ Preview**:
  - TYPE A: Gross = 13,000, ส่วนลด = 1,300, Net = 11,700
  - TYPE B: Gross = 10,000, ส่วนลด = 1,500, Net = 8,500
  - TYPE C: Gross = 10,000, ส่วนลด = 2,000, Net = 8,000
- [ ] กด Confirm → **ตรวจว่าเกิด Invoice 3 ใบพอดี** (INV-A, INV-B, INV-C)
      เลขที่ต้องเป็นรูปแบบ `INV-A-202608-0001` เป็นต้น
- [ ] เปิดแต่ละ Invoice → ตรวจว่า**ผลรวมของแต่ละรายการ = ยอดรวมหัว Invoice
      เป๊ะ** (จุดที่เคยมี Rounding Drift มาก่อน — ต้องตรวจละเอียด)
- [ ] เปิด Order เดิม → ต้องเห็นลิงก์ไป Invoice ทั้ง 3 ใบ (Parent Order
      Relation)

## 4. Cancel Flow

- [ ] พยายาม Cancel Order ที่มี Invoice แล้ว → ต้องถูก **Block** พร้อม
      ข้อความแจ้งชัดเจน
- [ ] Cancel Invoice ทั้ง 3 ใบก่อน → ค่อย Cancel Order สำเร็จ

## 5. Print & เอกสาร

- [ ] พิมพ์ Sales Order, Invoice, Tax Invoice (Auto จาก Invoice, VAT
      100%) → ตรวจว่าเลย์เอาต์ไม่แตก ตัวเลขจำนวนเงินเป็นภาษาไทยถูกต้อง
- [ ] ทดสอบพิมพ์จริงบนเครื่อง EPSON LQ-310 กับกระดาษต่อเนื่อง 9"×11" จริง
      → ตรวจตำแหน่งขอบกระดาษ (`src/lib/print-settings.ts` คือจุดที่ต้อง
      ปรับถ้าเพี้ยน)
- [ ] สร้างใบกำกับภาษีแบบ Manual (เลือกรายการเอง) → ตรวจว่ายอด VAT ที่
      คำนวณถูกต้อง
- [ ] สร้างใบวางบิลจาก Invoice 2-3 ใบ → ตรวจว่า Invoice ที่เลือกไปแล้ว
      ไม่โผล่มาให้เลือกซ้ำในใบวางบิลถัดไป

## 6. Excel Import/Export

- [ ] ดาวน์โหลด Template ลูกค้า → กรอกข้อมูล 3-5 แถว (มีแถวซ้ำ 1 แถว
      ตั้งใจ) → Import → ต้องเห็น error แถวที่ซ้ำ และ import สำเร็จเฉพาะ
      แถวที่ถูกต้อง
- [ ] Export Summary/Raw Data จากหน้า Report → เปิดไฟล์ดูว่าตัวเลขตรงกับ
      หน้าจอ

## 7. Backup/Restore

- [ ] กด "สำรองข้อมูลตอนนี้" → ไฟล์ .dump ถูกสร้างจริง ดาวน์โหลดได้
- [ ] (ทำในเครื่องทดสอบเท่านั้น ห้ามทำกับข้อมูลจริง) ทดสอบ Restore จาก
      ไฟล์ backup ที่เพิ่งสร้าง → ข้อมูลต้องกลับมาครบเหมือนเดิม

## 8. Audit Log

- [ ] เปิด `/audit-log` → ต้องเห็น log ของทุกการกระทำที่ทำมาข้างต้น
      (สร้างลูกค้า, ตั้งราคา, Confirm Order, Cancel ฯลฯ)
